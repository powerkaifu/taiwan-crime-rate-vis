# 步驟完成收尾流程

本次要收尾的步驟：$ARGUMENTS

依序執行，任何一步失敗就停下來回報使用者，不要跳過。

## 一、檢查

1. 執行 `npm run check`，必須顯示「全部通過」。
2. 執行 `npm run build`，必須成功且沒有警告。
3. 用瀏覽器打開網站，操作本步驟相關的功能，確認主控台沒有錯誤。

## 二、截圖

1. 截下本步驟相關畫面，存到 `docs/網站製作/screenshots/`。
2. 檔名：`step<步驟>-<圖表>-<案類>-<模式>.png`，例如 `step11-B-暴力.png`。
3. 截圖前把滑鼠移開圖表，避免懸停狀態被截進去。
4. 如果目前環境無法截圖，請使用者手動截圖並告知檔名。

## 三、更新文件

1. `docs/網站製作/實作規格書.md`：在對應步驟標 ✅、日期，並用一兩句話記下做了什麼、遇到的坑。
2. `docs/待辦備忘錄.md`：完成的項目把 `[ ]` 改成 `[x]`。
3. 若改到使用者看得到的功能，檢查 `README.md` 的互動速查表是否需要更新。

## 四、commit

1. 先執行 `git status`，只 `git add` 本步驟的檔案（程式、截圖、文件）。
2. 不要加入 `data/csv/` 的換行符號差異，也不要加入 `node_modules`、`dist`。
3. commit 作者用 `KaiFu <powerkaifu@gmail.com>`，訊息用繁體中文：

   ```
   <類型>: <摘要>（第 N 步）

   - 做了什麼 1
   - 做了什麼 2
   ```

   類型用 `feat`、`fix`、`docs`、`chore`。
4. 不要 `git push`。

## 五、回報

用三到五句話告訴使用者：完成了什麼、commit 編號、截圖檔名、下一步是什麼。然後停下來等使用者批准。

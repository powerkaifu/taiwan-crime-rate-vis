# 期中報告 Template 分析：老師想看到什麼

> 分析對象：`docs/VIS_Final_Proposal_template_backup.pptx`（19 頁，16:9）
> 本檔只分析範本，**還沒有寫我們的內容**。

---

## 一、這份範本是什麼

- 它是老師做的一份**「20 分鐘提案報告的示範」**。封面寫著 `INFORMATION VISUALIZATION · 20-MINUTE EXAMPLE`。
- 示範題目借用一篇真實論文：Hu, Liao & Chi（2024）〈Visual Exploration Framework of Intersecting Users and Activities between Issues in Social Media〉，JISE 40(2), 265–282。
- 封面特別註明：**「教學用 Proposal 重組：方法與設計說明 ≠ 原論文的逐頁重現」**。意思是老師把一篇論文「改寫成提案的樣子」，讓學生看懂提案該有哪些段落、怎麼論述，**不是要大家去報告這篇論文**。
- 檔名是 `VIS_Final_Proposal`，對應課程的 **Midterm Proposal（期中提案，20%）**：提的是「期末專題要做什麼」。課程時程：11/19 繳交書面 Proposal；12/10 進度報告；12/31 期末報告。

---

## 二、老師的用意（從範本歸納）

1. **報告要照「研究的邏輯」走，不是照「做了哪些圖」走**：動機 → 問題 → 相關研究 → 資料 → 任務 → 設計理論 → 視覺編碼 → 介面 → 展示 → 評估 → 結論。
2. **Munzner 的 Why–What–How 是骨架**：範本有專頁講 Nested Model，還要求 Requirements（需求）和 Tasks（任務）分開寫，最後要有 Validation（怎麼驗證）。
3. **要和既有方法比較**：Related Work 兩頁，一頁列方法類別，一頁做「比較矩陣」，說明既有方法缺什麼、我們補什麼。
4. **圖片必須是真的**：範本裡每個放圖的位置都寫著「原論文圖片置入區」、「尚未取得原始圖檔，**未放入自行創作示意圖**」、「不以外部圖替代」、「**若論文未提供動畫，勿宣稱原生動畫**」。老師非常在意**不能用假的示意圖或虛構動畫充數**，要用實際系統的截圖，並標註圖號與說明。
5. **靜態、動態、互動要分開說明**：第 12、15、16 頁分別是靜態視覺化、動態視覺化（狀態變化與探索流程）、互動（Interaction Mapping），對應課程 HW1～HW3 的三種能力。
6. **Dashboard 不是把圖拼在一起**：結論頁寫「Dashboard 不是多張圖的拼接，而是任務導向的協同設計」。要說明每個面板對應哪個任務、選取狀態如何在各視圖一致。
7. **要有情境式 Demo 影片（2–3 分鐘）**：用一個具體情境（誰、要回答什麼問題）分步驟操作，最後回應 Research Questions。影片要錄「原系統」，不用虛構動畫。
8. **要有評估計畫，而且和原研究分開**：量化（完成率、時間、錯誤）＋質化（Think-Aloud、訪談）＋對照組（基準圖表或無互動介面）。範本特別提醒：「原論文實驗與提案評估需分開」。
9. **時間分配固定**：5 段 × 4 分鐘＝20 分鐘（第 2 頁）。

## 三、逐頁說明

| 頁 | 範本標題 | 老師要這頁回答的問題 | 範本裡的提醒 |
| :-- | :-- | :-- | :-- |
| 1 | 封面 | 題目、案例來源、作者 | 標明是「Proposal 重組」，不是逐頁重現 |
| 2 | 20 分鐘報告架構與時間分配 | 報告分哪 5 段、各幾分鐘 | 每段 4 分鐘 |
| 3 | 研究動機 | 為什麼這個問題值得做？現有做法不足在哪？研究目的是什麼？ | 結尾要有一句「研究目的」 |
| 4 | Research Questions 與預期貢獻 | 列出 RQ1～RQ3；預期貢獻是什麼 | RQ 要能在 Demo 時回應 |
| 5 | Related Work：方法與侷限 | 相關方法有哪幾類？各自能做什麼？要比較哪些能力？ | 「需引用正式比較表與文獻」 |
| 6 | Related Work：對應比較矩陣 | 方法 × 能力的表格（有／有限／視實作） | 「最終報告請逐項核對」，不能憑印象 |
| 7 | Data Analysis：原始資料與抽象 | 資料有哪些實體？前處理與 EDA 做了什麼？ | 清理、建立關聯、彙總、看分布 |
| 8 | Requirements 與 Tasks（Why） | 使用者需求 R1～R4；對應的任務 T1～T4（Discover、Compare、Filter、Identify…） | Requirements 和 Tasks 分兩欄 |
| 9 | Munzner Nested Model | Domain／Why／What／How／Validation 各一句 | Validation：完成度、錯誤率、效率、可用性 |
| 10 | System Overview | 系統整體介面，說明每個面板對應哪個 Task | 放實際介面圖，標圖號與說明 |
| 11 | Visual Encoding | 資料屬性對應哪個視覺通道？設計理由是什麼？ | 不用面積做精確讀值、類別色一致、要有圖例與尺度 |
| 12 | 靜態視覺化 | 固定快照下呈現什麼結構？屬性如何對應面積或色彩？有效性與限制？ | 用實際圖，不用外部圖替代 |
| 13 | Glyph | 個體層次的摘要設計 | 這是示範論文特有的元件；我們沒有對應的設計時要另外處理（見第四節） |
| 14 | Dashboard：多視圖的空間配置 | Overview／Focus／Detail 怎麼擺？選取狀態如何協同？ | 以實際介面圖為準 |
| 15 | 動態視覺化 | 狀態如何變化？選取前後視圖如何更新？ | 「區分時間變化與互動狀態變化」；沒有動畫不要宣稱有 |
| 16 | 互動式視覺化：Interaction Mapping | Select／Filter／Highlight／Details on Demand 各做什麼 | 用選取前／後的實際畫面對照 |
| 17 | Demo Video（2–3 分鐘） | 一個情境、四個步驟，最後回應 RQ | 錄實際系統，不用虛構動畫 |
| 18 | Evaluation Plan | 怎麼證明視覺化有效？量化＋質化＋對照 | 和既有研究的實驗分開寫 |
| 19 | 結論、限制與參考來源 | 重點結論、限制、引用 | Why–What–How 串連；Dashboard 是任務導向 |

## 四、對照我們的專案：已有什麼、缺什麼

我們的題目是「同一份資料，排序差多少？——台灣 22 縣市犯罪率與破獲率的互動視覺化」，**網站已經做出來了**，所以範本裡所有「原論文圖片置入區」，都可以用**我們網站的真實截圖**，正好符合老師「不用假圖」的要求。

| 範本要求 | 我們目前的狀況 |
| :-- | :-- |
| 動機、研究目的 | 有（期中簡報 Slide 1～3） |
| Research Questions | **要整理**：目前有問題意識，但還沒寫成 RQ1～RQ3 的形式 |
| Related Work（方法類別＋比較矩陣） | **缺最多**：目前只有「重製對象」（想想論壇表 2），沒有和其他視覺化方法或文獻的比較表 |
| Data Analysis（實體、前處理、EDA） | 有素材：兩個 CSV、清理規則、衍生欄位（名次、推估人口、95% 區間），寫在規格書 §3 |
| Requirements 與 Tasks | 有 Tasks（Compare、Identify、Lookup、Discover）；**Requirements 要另外寫成 R1～R4** |
| Nested Model（含 Validation） | 有 Why–What–How；**Validation 要補** |
| System Overview、Dashboard | 有實際網站，可截圖 |
| Visual Encoding（含設計理由） | 有（README、更正單、Demo 指南） |
| 靜態／動態／互動三頁 | 有：靜態（三張圖）、動態（件數 ⇄ 犯罪率重排轉場）、互動（懸停、鎖定、篩選、資料表） |
| Glyph | **沒有對應設計**，需要決定換成其他內容（例如等積方塊地圖或名次更正欄），或刪掉這頁 |
| Demo 影片（情境 4 步驟） | 待錄；可用發現卡當情境 |
| Evaluation Plan | 有雛形（模擬使用者測試 5 題）；**正式量化／質化計畫要補** |
| 結論、限制、參考來源 | 有限制說明與部分文獻；參考來源要整理 |

## 五、需要先跟老師或組員確認的事

1. **範本是「論文改寫成提案」，我們是「重製新聞視覺化」**：Related Work 是否要比照範本，找學術文獻做比較矩陣？還是可以用「既有新聞與政府統計圖表」作比較對象？
2. **頁數是否要完全照 19 頁**：例如 Glyph 頁，我們沒有對應的設計時，可否替換或刪除？
3. **20 分鐘是全組總時間嗎**：時間分配是否要照 5 段 × 4 分鐘？
4. **書面 Proposal（11/19）** 是不是就交這份 PPT，還是另外要一份書面報告？
